# dispatching-subagents — body test record

The description was tested when the skill was written; the body was not. Review called the body a
paranoid manifesto — organised by incident rather than by decision — and that critique was correct.
This is the record of testing the body and rewriting against what the test found.

## Method

Three scenarios, each run in two arms: an agent with no access to any guidance file, and an agent
told to read the skill and follow it. Both arms answered the same prompt; the skilled arm was
additionally asked to report where the file left it guessing, gave advice it could not act on, or
made it read content that did not apply.

Scenarios were chosen to cover a rule the skill teaches, a topic it omits, and a rule it teaches
under pressure to abandon:

1. **Write the dispatch** for a cross-tenant cache-key leak.
2. **Plan the execution** of a 43-site migration plus a review pass — agent count, batching,
   barriers, workflow-vs-subagent, model tier.
3. **Decide whether to run another review round** after five rounds of flat finding counts.

## RED — what the unaided baseline actually does

| Scenario | Baseline behaviour |
| --- | --- |
| 1. Brief | **Fails.** Prescribed the mechanism twice — "so the tenant id is always part of the cache key", "take tenant id as an explicit parameter rather than reaching into global state". No refusal clause. Described a report and never commanded its delivery. |
| 2. Plan | **Passes unaided.** Correct topology, disjoint file batches, barrier before the shared gate, sensible model tiers — none of it prompted. |
| 3. Stop call | **Passes, with one defect.** Read the flat count correctly, then embedded "cap at round 7 regardless" — a round cap, which is the instrument the skill exists to remove. |

Scenario 2 is the finding that changed the plan. The rewrite had been scoped to *add* coverage of
splitting, topology and barriers, on the theory that a skill named `dispatching-subagents` should
cover them. The baseline answers that unaided and well, so that section was never written — a skill
earns tokens by correcting a failure, and there was no failure to correct. Model and effort
selection stayed out for a different reason: the delegation rule already carries it, and the
skilled arm sourced it from there correctly and said so.

## Defects the skilled arm found

1. **No seam between the two halves.** "I had to read past it and consciously discard roughly a
   third of the file's content." Independently reproduced the review critique.
2. **The central rule was undefended at its hardest point.** "The defect itself — the key omits
   tenant id — is one short step from stating the fix. The skill never addresses the case where an
   accurate defect description and a mechanism prescription nearly coincide." Both prior examples
   were easy cases.
3. **"Mostly induced" / "mostly pre-existing" had no threshold** and no answer for a tie.
4. **The workflow preference had no boundary** and got applied to a plain parallel fan-out.
5. **Path guidance assumed the dispatcher already holds absolute paths.**

## What changed

A router at the top splitting one-shot dispatch from loop work, and a positive scope statement so
the omissions read as deliberate. A new section drawing the defect/mechanism line as a grammatical
test — **diagnosis is a noun phrase, mechanism is a verb phrase about the code; stop at the verb** —
with a worked pair whose good and bad versions share their first sentence. The stop table restated
to set *the scope of the next round* rather than a stop/go verdict, which dissolves ties without a
threshold. The workflow rule bounded. Anecdotes generalised or cut.

Body went from 1389 to 1593 tokens against a 2000 cap while gaining a section and losing a third of
its prose, because the incident narration was paying for the space.

## GREEN and REFACTOR

Re-run against the same three scenarios: the brief carried no prescribed mechanism and closed with
"a report that only exists on disk never reaches me"; the plan chose plain fan-out for the
migration and a workflow only for the rounds, calling the bounded workflow line "the highest-value
line in the file"; the stop call refused the round cap.

Two further scenarios tested the rewritten stop rule specifically — an even 2-induced/2-pre-existing
split, and a clean round that had been a broad sweep rather than a scoped one. Both resolved
mechanically. On the tie: *"No threshold problem to invent."* On the clean round, the agent refused
to ship under explicit budget pressure. That run found the last two gaps, both closed: "the newest
diff" was undefined for a mixed round, and budget exhaustion was not named alongside round count as
an invalid stop signal — the agent had to supply that equivalence itself.

A separate defect surfaced from the sanitizer, not from an agent: the rewritten provenance comment
no longer opened with `Source:`, which is the only marker the deploy gate recognises, so it would
have shipped as body text. Fixed, verified against the real sanitizer, and swept across `src/` —
no other asset has it.

## Honest limits

- Judges and workers were a mid-tier model. The real dispatcher is a frontier model, which may
  clear some of these bars unaided; the baseline arm already did on scenario 2.
- One replicate per scenario per arm. The failures found were unambiguous and reproduced across
  scenarios, but a one-pass green is weaker evidence than it looks — that is exactly how the
  description's q5 defect nearly shipped clean.
- Scenario 1's "look for a sibling" instruction could not be followed, because the harness forbade
  reading the repo. The skill's fallback covered it, but the primary instruction went untested.
- The description was **not** re-tested and **not** changed. Nothing in the rewrite alters what it
  claims, and its `review-verdict` boundary was tuned over two rounds at three replicates.
