## What this slice does

- **A clean lens report needs evidence its reviewer opened the target.** The reviewer's own output records no tool use on either transport, so the gate reads the attempt's retained stderr. - **A findings report is never refused this way.**

## What

Every seat the review panel dispatches has its effort and tool grant held as data in `contracts.json` and written into `round.json`, so the dispatcher never picks either one. A run that dies inside the model's reasoning is handled by a bounded ladder the dispatch gate records, not by routing a model away from a shape in advance. This is slice A of agents-config-9k9.408 under its 2026-10-07 restatement.

- **Pins.** `contracts.json` gains a `pins` block with one pin for each of the eight transport, tier and scope seats, one for the staffing recommender and one for the trend checkpoint. OpenRouter reads of a whole artifact run at `low` and reads of a change at `high`, at either tier; Codex `frontier` seats run at `high` and `mid` seats at `medium`. No pin names a model: the model comes from the `choosing-a-delegate` routing table by provider and tier.
- **Grants.** Every grant is the Codex read-only sandbox or a list drawn from `Read`, `Grep` and `Glob`. No pin grants a `Bash` pattern: `git diff --output=<path>` writes under `Bash(git diff *)`.
- **The change as a file.** The emitter writes `<lens>.diff` beside every lens's prompt, over that lens's scope for the round, and names it in the prompt, so a reviewer with no shell reads the change. Lenses sharing a revision pair share one computed diff. A diff `git` cannot compute refuses the round.
- **Round record.** Each lens entry gains `effort` and `tools`, copied from its seat's pin. A seat with no pin refuses the round with code `no-seat-pin` and writes nothing.
- **Rosters.** Each class keeps exactly one OpenRouter lens: `security`, `contract-only-boundary`, `ac-testability` and `global-consistency`. Four other lenses move to Codex. Every lens keeps the tier and re-review tier it declares on `main`, and the emitter keeps its tier-per-round rule.
- **The ladder, in the gate.** `dispatch_gate.py claim` takes `--effort` and records it. Its reasons gain `dead-run`, accepted only as the same model one effort step down or as the failover seat (the other transport at the same tier and scope); an off-ladder claim is refused without spending an attempt and the refusal names what the gate accepts next; the bound of three attempts stands, and a lens whose failover attempt also dies halts the round with the gate's halt guidance.
- **Doctrine.** `harvest.md` states the ladder, the plain failover seat, the diff file, the recommender's one re-run and stop, and the claim with its effort. Nine scenarios with keyed answers in `evals/dispatch-scenarios.md` check that a reader holding only the named files reaches the pinned dispatch, the failover seat and each ladder step.

## Why

The constraint this design rested on before, that the OpenRouter `mid` model never completes a whole-artifact read, has no run record behind it, and the only recorded reads of that shape on that model finished. A constraint stated without its variables cannot be scoped or falsified, so the design no longer encodes it: a seat that names a model runs that model, and the ladder answers for a dead run when one happens, recording every attempt. In this pull request's own review campaign the OpenRouter `mid` model read the whole change or document twenty times at its pin and finished every time.
