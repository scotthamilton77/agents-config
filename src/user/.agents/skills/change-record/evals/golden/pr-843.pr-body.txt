## Changes
- **Pins.** contracts.json pins effort and tools for every reviewer slot, and no reviewer gets a shell.
- **The change as a file.** The emitter writes one diff file beside each prompt.
- **Recovery sequence.** A run that died is retried one effort step lower, then on the other provider. The round halts after three attempts.
<details><summary>Design notes</summary>

The earlier design routed the OpenRouter mid-tier model away from whole-document reads. That constraint had no run record behind it, and the only recorded reads of that shape on that model had finished. A constraint stated without its variables cannot be scoped or falsified, so the design no longer encodes it. A slot that names a model runs that model. The recovery sequence answers for a death when one happens, and records every attempt. During this pull request's own review that model finished 20 whole-document reads in 20.

Rejected: letting the dispatcher pick a fallback model freely. That hides the cost decision in a prompt and leaves no record. Rejected: a shell grant restricted by a command prefix. Both `git diff` and `git log` accept `--output`, so a prefix pattern is not read-only.

contracts.json holds eight slots by provider, tier and read scope, plus the staffing recommender and the trend checkpoint. OpenRouter reads a whole document at low effort and a diff at high. Codex frontier slots run at high and mid slots at medium. No pin names a model, because the routing table does that. Every tool grant is the Codex read-only sandbox, or a list drawn from Read, Grep and Glob. No reviewer gets a shell pattern, because `git diff --output=<path>` writes a file.

The emitter writes each diff file over that reviewer's scope for the round, so a reviewer with no shell can still read the change. Reviewers sharing a revision pair share one computed diff. Each reviewer entry in the round record gains effort and tools copied from its pin. A slot with no pin refuses the round and writes nothing.

Each artifact class keeps exactly one OpenRouter reviewer. Four reviewers move to Codex. Declared tiers do not change.

The gate's claim command takes `--effort` and records it. A run that died may be claimed again only as the same model one effort step lower, or as the other provider at the same tier and scope. Anything else is refused and costs no attempt. After three attempts the round halts with guidance. A revert restarts a round in flight, because its attempts ledger gained a field.

harvest.md states the sequence, the failover slot, the diff file and the claim form. Nine scenarios with expected answers check that a reader holding only those files reaches the right dispatch.

The criteria attack panel needs the same pins, as slice B of this work item, and it is a different skill with its own configuration file.

The round record copies each pin, and tests check that too. This pull request's own first round ran every reviewer at its pin, on two vendors, with no substitution. Both recovery failures were real bugs found in review, reproduced, and fixed with a failing-then-passing test each. A stuck round also costs coverage, because it can look finished with one reviewer never having read the change.

The written doctrine could send whoever runs a round by hand down the wrong path. Nine written situations were answered by a model given only the doctrine files, and all 27 answers, three runs each, matched the expected dispatch. A reviewer without a shell could miss the change if its diff file were missing or covered the wrong scope. Tests cover the diff file's content, an empty change and an unknown revision, and a diff git cannot compute refuses the round before anything is dispatched.
</details>
