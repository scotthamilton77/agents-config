# Error codes

Every code each script emits. Each writes one JSON object to stdout and never a traceback, so a
caller parses the same shape on success and on failure. `--help` is neither, and prints usage the
way every command does — exiting 0, which for a run that checked something means complete. A caller
reading either stdout or the exit status should not pass it.

## `emit_prompts.py`

Refusals print `{"emitted": false, "errors": [{"code", "message"}]}` and exit 2.

| Code | Condition |
| --- | --- |
| `no-spec` | No `--spec` given, or the document is missing, unreadable, or empty. |
| `untrimmed-spec-path` | The `--spec` document's name carries surrounding whitespace. The record that closes the round is committed beside the document and named from that basename with the whitespace dropped, and the check refuses a record naming its document that way — its row below says why — so a round over `ledger.md ` would emit, cost every model in the panel, and come back to a record standing under the name `ledger.md` beside it already owns, which nothing can close. Rename the document. |
| `invisible-spec-path` | The `--spec` document's name carries a character that renders as nothing — a zero-width space, a byte-order mark, a control character, an unassigned codepoint — which `strip` leaves standing, so the name a reader sees and the file that spelling opens are two documents. Anywhere in the name, since one written inside the extension comes off with it when the record's name is derived. The same round the check refuses, refused before it runs. Every letter, mark and digit of every script renders, so a document named in Japanese or with an accented character is named legibly and is attacked. Rename the document. |
| `spec-contains-marker` | The document carries an untrusted-content marker of its own. Fencing it would rewrite the text its revision names, so the round refuses rather than attack something the record cannot name. |
| `no-lenses` | The lens registry, every directory under `lenses/` holding a `prompt.md`, does not yield one usable attacker per lens: it holds none; a lens's front matter omits `tier`, `transport`, `standard` or `enforces` or leaves one blank, `enforces` names no rule, or the body is blank, which is a lens that cannot do its job while the round claims it ran; two lens names are one name the way the filesystem matches them, and a lens's name is its prompt's filename, so the second lens's prompt would overwrite the first; a name is not a bare filename, whose prompt would land outside the owner-only directory the round created; `standard` is not `acceptance-criteria`, or `enforces` names a rule ID the standard has no heading for, so the lens would go out without the rule it judges by; or `workings` is anything but `required`, or is `required` with no JSON object in the lens's `workings.schema.json`, which leaves an inventory nothing can judge. Each would report an emitted round while an attacker it declared never ran. |
| `unknown-lens` | `--lens` names a lens the registry does not hold. Nothing is written, and the message lists the lenses it does hold. |
| `no-standard` | The `acceptance-criteria` skill is not installed beside this one, or its body holds no `### ` rule once its front matter is set aside. Every attacker judges criteria against that standard, so a round without it would be the attack the standard replaced while reporting itself emitted. Install that skill, or run from a tree that holds it. |
| `no-out-dir` | No `--out-dir` given, or it could not be created — including when a parent of it does not exist, since the round creates one directory and no parent along the way. The output names are fixed, so a round with nowhere named truncates whatever wears them in the directory it ran from. |
| `unsafe-output-path` | The out-dir is a symbolic link, or an output name is held by a link of either kind or by something that is not a plain file — writing would take the whole document somewhere the round never named. Also when the `--spec` document is itself the file standing at an output name: a plain file there is overwritten as ordinary re-emission, so a round pointed at the directory the document sits in would destroy the artifact under attack and report itself emitted. Name an out-dir that does not hold the document. Also when the out-dir cannot be listed, or holds a Markdown file this round does not write — a prompt for a lens since retired, or one over another document, which a caller dispatching the directory rather than the round file sends, and whose report is then recorded as coverage of this round. Only Markdown names are held to that, since nothing else is dispatched as a prompt; the round deletes nothing and names every file at fault at once. |
| `bad-arguments` | The command line could not be parsed. |
| `emitter-failure` | Anything else that escaped, reported rather than raised so stdout stays a contract. Every refusal above is decided before any file is written, and every prompt is rendered before any is written, so a refused round leaves nothing behind. A write that fails partway — the disk filling, say — is the one case that can, and `round.json` is written last, so a directory without it holds no round. Read the exit status rather than the directory. |

## `assemble_record.py`

Refusals print `{"assembled": false, "errors": [{"code", "message", "lens"?}]}` and exit 2. Every
refusal is decided before anything is written, so a refused step leaves no union, skeleton or
record behind, and never overwrites one already there. A step reports every refusal it finds, so one
run names every lens to rerun and every disposition to fix.

| Code | Condition |
| --- | --- |
| `bad-arguments` | The command line could not be parsed, a `--report` is not `<lens>=<path>`, one lens is named twice, or a lens is named that the round does not name. |
| `bad-round` | The round file is unreadable, or does not name the document, the revision attacked, and each lens exactly once. |
| `missing-lens-output` | A lens the round names has no `--report`, or its output cannot be read. Run that lens again. |
| `empty-lens-output` | A lens's output is blank, or is a Codex envelope whose `rawOutput` is blank. Run that lens again. |
| `unparseable-lens-output` | A lens's output holds no JSON object carrying `report` or `objections`. Run that lens again. |
| `unusable-lens-output` | Every objection a lens returned is malformed. That is not a report that found nothing, so it is not recorded as one. Run that lens again. |
| `unrepairable-drift` | A lens's report departs from the output shape in a way no repair can make without guessing what the attacker meant. `record.md` lists these cases. Run that lens again. |
| `bad-union` | The union is unreadable, or is not one the union step wrote. |
| `no-spec` | The `--spec` document cannot be read. |
| `spec-mismatch` | The `--spec` document's name is not the one the round attacked. The record is named from the document and goes beside it. |
| `bad-dispositions` | The dispositions file is unreadable, or is not a list of objects in the skeleton's shape. |
| `malformed-disposition` | An entry's id is not a string, its `disposition` is not `accepted` or `rejected`, it carries a key the skeleton does not, or it lacks the field its verdict needs: `covering_ac` on an acceptance, `rationale` on a rejection. |
| `missing-disposition` | An objection in the union has no entry. |
| `unknown-disposition-id` | An entry names an id the union does not hold. |
| `duplicate-disposition` | An id carries more than one entry. |
| `stale-disposition` | An entry's `objection` text is not the text the union holds under its id. The entry was written against another objection, typically before a lens was rerun. |
| `revision-mismatch` | An entry supplies a `revision` that does not name the document's current bytes. Leave it out; the step computes it. |
| `assembler-failure` | Anything else that escaped, reported rather than raised so stdout stays a contract. |

## `check_record.py`

Results print `{"clean", "complete", "errors": [{"code", "id"?, "message"}], "document"?,
"revision"?}`. Exit 0 complete, 1 not complete, 2 unusable input.

| Code | Condition |
| --- | --- |
| `no-record` | No record was named. An unnamed record is not an unattacked one. |
| `unreadable` / `invalid-json` | The record is missing, undecodable, or not JSON — including a record that parses as JSON and writes one key twice in an object. The grammar allows that and every reader silently keeps one of the two, so the text a reviewer reads and the record the check adjudicates would differ with nothing to show for it. |
| `schema` | The record is the wrong shape, including a disposition missing the fields its verdict requires — `revision` and `covering_ac` on an acceptance, `rationale` on a rejection. |
| `bad-arguments` | The command line could not be parsed. Options are matched in full, never by an unambiguous prefix: the ordering declaration is read off the raw command line, and a spelling accepted there but invisible to that reading would drop an ordering violation on a line that failed to parse. |
| `checker-failure` | Anything else that escaped, reported rather than raised so stdout stays a contract. |
| `no-spec` | `--spec` was given without a document, or the attacked document is one the emitter would not have read: bytes that are not UTF-8 text, or nothing but whitespace once byte-order marks are set aside, which `strip` leaves standing. Each is refused before a prompt goes out, so no round in hand attacked one, and closing a round over an empty stub clears work to start against criteria nobody wrote. Judged over the document in front of the check whichever revision that is, since neither condition can be produced by carrying an objection into the document: no incorporation empties a document or takes its text out of UTF-8. The emitter's refusal is what stops such a round existing; this catches the record written without one. |
| `spec-contains-marker` | The attacked document carries an untrusted-content marker of its own — the emitter's row above says why it refuses rather than rewrite what it hashed. Asked only where the document on disk is the revision the round attacked, unlike `no-spec`: a criterion accepted into the document may quote the marker, and the revision attacked is a hash whose content cannot be recovered to be held to the same test, so refusing after an acceptance would close no round over that document again — over text every attacker in it read without the marker. |
| `record-name-mismatch` | The record's filename is not the one the document it names would give it: `spec_path` without its extension, plus `-ac-attack.json`. The document is found beside the record, so that pair of names is the whole of what binds the two, and a record standing under a second document's name closes a round over a document no attacker in it read. Decided on the record's own basename against its `spec_path`, whatever `--spec` points at. Whether the derived name and the record's own are one name is asked of the volume rather than decided on the spelling: a reader reaches this record by looking that name up beside the document, so what the lookup reaches is the answer. Comparing exactly would refuse a correctly bound round where the volume folds case; folding would admit one where it does not, and there the two spellings are two documents. Only the last extension comes off: `ledger.v2.md` gets `ledger.v2-ac-attack.json`, and a document with no extension gets its whole name plus the suffix. |
| `spec-unreadable` | The document is not where the record says. The record names it relative to its own directory; `--spec` overrides that when it has moved. |
| `invisible-spec-path` | The record's `spec_path` carries a character that renders as nothing, which `strip` leaves standing because it is not whitespace to it. The name a reader sees and the file that spelling opens are two documents then, and one sitting in the extension comes off with it when the record's own name is derived — so the record stands under the legible document's name while closing a round over a file that document is not. See the emitter's row above; a name written in any script is fine, since only characters nothing renders are refused. |
| `untrimmed-spec-path` | The record's `spec_path` carries surrounding whitespace. The name a reader sees on the page and the file that spelling opens are two documents then, and the record's own name is derived with the whitespace gone — `ledger.md ` drops to the stem `ledger`, so the record stands under the name the document `ledger.md` beside it already owns while closing a round over a file that document is not. |
| `spec-not-a-bare-filename` | The record's `spec_path` reaches out of the record's own directory, or is absolute. A record is committed beside the document it names, so its basename is what finds it and what the record's own name is derived from; anything else decides the round against a document the record does not sit next to, and resolves only on the machine that wrote it. Judged on the record whether or not `--spec` names a document, since `spec_path` is what the record claims regardless of where the document is read from. |
| `untrimmed-revision` | A revision keeps the newline `git hash-object` prints. That newline compares unequal to the same content written without it, so an acceptance that changed nothing would pass as an incorporation. In practice this is the only surrounding whitespace that reaches here: every other form fails the schema's pattern first and is reported as `schema`. Judged over the revisions the adjudication reads — the one attacked, and the first acceptance of each objection the round holds. One left on a rejection, on a disposition naming an objection the round does not hold, or on a second verdict for an objection already judged decides nothing, and refusing the record over it would hide the error that names the disposition itself. |
| `no-lenses` | The bundled lens registry is one the emitter would refuse to emit from — see its row above. Coverage is read off that registry, so a round in hand cannot have come from a registry like this, and reading coverage off it credits the record with attackers that never ran. The rule IDs the lenses enforce are judged only where the standard is found; where it is not, the emitter refuses every round as `no-standard`, which is a fault of the installation rather than of the registry. |
| `mixed-revision-notation` | The record writes revisions in both notations, so one content would read as two revisions and an acceptance that changed nothing could pass as an incorporation. Judged over the same revisions as `untrimmed-revision`: a notation used only where nothing reads it refuses nothing. |
| `lens-missing` | A declared lens has no report. A lens that errored or returned unreadable output leaves the round unfinished, and an empty objection list never stands in for a report. Coverage is containment, not equality: the declared set must be reported, and a record reporting more than that is surplus coverage rather than a defect — so retiring a lens leaves the rounds it ran in closed, where adding one reopens them. A misspelled lens name still refuses the round, since the lens it was meant to name goes missing. |
| `duplicate-lens` | A lens reports more than once. Coverage is read off one entry per lens. Names are matched the way the filesystem matched them when the prompts landed, so two spellings differing only in case or in Unicode form are one lens reporting twice rather than two lenses — they were one prompt file and so one attacker. Fires on any repeated name, including one the registry no longer declares. |
| `unreported-objection-lens` | An objection is attributed to a lens that files no report in this round. A lens that produced an objection reported, so this one traces to no attacker the record names. Held against the record's own reported set rather than the registry's declared one: a record naming a retired lens carries an entry for it, so its objections still trace and the round stays closed. |
| `ground-outside-lens` | An objection's `ground.rule` is not a rule its producing lens enforces. A lens's prompt carries only the rules it enforces, so an objection citing another was not produced by that lens's instructions. An objection from a lens the registry no longer declares is not judged, since what that lens enforced is on record nowhere the check reads. |
| `invalid-workings` | A lens whose front matter requires workings reported without them, or with workings its `workings.schema.json` refuses, or with one part ID used twice. Its findings are read off that inventory, so the lens returned nothing usable: run it again rather than record it without one. |
| `unreported-residue` | A lens's valid workings leave a part no criterion discharges, or list a criterion that discharges no part, and no objection from that lens names it: the part in `obligation`, the criterion in `target_ac`. The message names the part or criterion. The finding was made and the record lost it. |
| `contradicted-empty-report` | A lens reports empty, yet objections are attributed to it. |
| `contradicted-objections-report` | A lens reports objections, yet none are attributed to it — an objection it made and the record lost is a hole nobody adjudicates. |
| `duplicate-objection-id` | Two objections carry one id, so a disposition naming it adjudicates neither. |
| `unadjudicated-objection` | An objection has no disposition. The round closes only once every objection is accepted or rejected. |
| `duplicate-disposition` | One objection is adjudicated more than once. |
| `unknown-objection-id` | A disposition names an objection the round does not hold. |
| `unincorporated-acceptance` | An acceptance names the revision it attacked. Accepting an objection without changing the document leaves it unadjudicated. |
| `stale-revision` | The document is not carrying every revision the record accounts for: in a round that accepted something, one an acceptance names; in a round that accepted nothing, the revision attacked. Either the document moved on after the round, and the new revision must be attacked or the objections re-adjudicated against it — or an accepted objection's incorporation never landed, and the edit is missing. A record whose acceptances name several different revisions always lands here: the document can only be in one state, so acceptances name the revision it reached once every accepted objection was in it. Before editing the document, check the revision was written the way the check reads one: take the object id with `git hash-object --no-filters`, since the plain form runs the repository's clean filters and a document with CRLF endings then hashes as though its endings were LF. |
| `ordering-violation` | `--implementation-started` was declared — written bare, since a denial in either spelling (`--implementation-started=false` or `--implementation-started false`, over `false`, `0`, `no`, or `off`) declares nothing — and this run did not close the round — including when it could not read far enough to judge one, since a record that cannot be read has certainly not closed anything. The attack runs before that work, never alongside it. A denial declares nothing and does not make the command line valid either: the flag takes no value, so the `=` spelling is refused as `bad-arguments`, and one written after a space is an argument nothing accepts when a record was named, which is `bad-arguments`, or is taken for the record's own name when none was — and the run then answers whatever reading a record by that name gives. |
