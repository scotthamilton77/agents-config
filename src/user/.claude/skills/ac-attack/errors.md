# Error codes

Every code either script emits. Both write one JSON object to stdout and never a traceback, so a
caller parses the same shape on success and on failure.

## `emit_prompts.py`

Refusals print `{"emitted": false, "errors": [{"code", "message"}]}` and exit 2.

| Code | Condition |
| --- | --- |
| `no-spec` | No `--spec` given, or the document is missing, unreadable, or empty. |
| `spec-contains-marker` | The document carries an untrusted-content marker of its own. Fencing it would rewrite the text its revision names, so the round refuses rather than attack something the record cannot name. |
| `no-lenses` | The lens registry does not yield one usable attacker per declared lens: it names none; omits a key an entry owes (`lens`, `mandate`, `tier`, `transport`) or leaves one blank, which is a lens that cannot do its job while the round claims it ran; names one lens twice, and a lens's name is its prompt's filename, so the second mandate would overwrite the first; or names one that is not a bare filename, whose prompt would land outside the owner-only directory the round created. Each would report an emitted round while an attacker it declared never ran. |
| `no-out-dir` | No `--out-dir` given, or it could not be created — including when a parent of it does not exist, since the round creates one directory and no parent along the way. The output names are fixed, so a round with nowhere named truncates whatever wears them in the directory it ran from. |
| `unsafe-output-path` | The out-dir is a symbolic link, or an output name is held by a link of either kind or by something that is not a plain file — writing would take the whole document somewhere the round never named. Also when the `--spec` document is itself the file standing at an output name: a plain file there is overwritten as ordinary re-emission, so a round pointed at the directory the document sits in would destroy the artifact under attack and report itself emitted. Name an out-dir that does not hold the document. |
| `bad-arguments` | The command line could not be parsed. |
| `emitter-failure` | Anything else that escaped, reported rather than raised so stdout stays a contract. Every refusal above is decided before any file is written, and every prompt is rendered before any is written, so a refused round leaves nothing behind. A write that fails partway — the disk filling, say — is the one case that can, and `round.json` is written last, so a directory without it holds no round. Read the exit status rather than the directory. |

## `check_record.py`

Results print `{"clean", "complete", "errors": [{"code", "id"?, "message"}], "document"?,
"revision"?}`. Exit 0 complete, 1 not complete, 2 unusable input.

| Code | Condition |
| --- | --- |
| `no-record` | No record was named. An unnamed record is not an unattacked one. |
| `unreadable` / `invalid-json` | The record is missing, undecodable, or not JSON — including a record that parses as JSON and writes one key twice in an object. The grammar allows that and every reader silently keeps one of the two, so the text a reviewer reads and the record the check adjudicates would differ with nothing to show for it. |
| `schema` | The record is the wrong shape, including a disposition missing the fields its verdict requires — `revision` and `covering_ac` on an acceptance, `rationale` on a rejection. |
| `bad-arguments` | The command line could not be parsed. Options are matched in full, never by an unambiguous prefix: the ordering declaration is read off the raw command line, and a spelling accepted there but invisible to that reading would drop an ordering violation on a line that failed to parse. |
| `checker-failure` | Anything else that escaped, reported rather than raised so stdout stays a contract. |
| `no-spec` | `--spec` was given without a document, or the attacked document is one the emitter would not have read: bytes that are not UTF-8 text, or nothing but whitespace once byte-order marks are set aside, which `strip` leaves standing. Each is refused before a prompt goes out, so no round in hand attacked one, and closing a round over an empty stub clears work to start against criteria nobody wrote. Judged over the document in front of the check, which is the revision attacked only in a round that accepted nothing: an acceptance moves the document on, and what it held when the attackers read it is not recoverable from a revision. The emitter's refusal is what stops such a round existing; this catches the record written without one. |
| `spec-contains-marker` | The attacked document carries an untrusted-content marker of its own — the emitter's row above says why it refuses rather than rewrite what it hashed. No round in hand attacked this text. Judged over the same document, and so within the same scope, as `no-spec`. |
| `record-name-mismatch` | The record's filename is not the one the document it names would give it: `spec_path` without its extension, plus `-ac-attack.json`. The document is found beside the record, so that pair of names is the whole of what binds the two, and a record standing under a second document's name closes a round over a document no attacker in it read. Decided on the record's own basename against its `spec_path`, whatever `--spec` points at, and matched the way the filesystem matches names — two spellings differing only in case or Unicode form are one name there, and holding them apart would refuse a round correctly bound. Only the last extension comes off: `ledger.v2.md` gets `ledger.v2-ac-attack.json`, and a document with no extension gets its whole name plus the suffix. |
| `spec-unreadable` | The document is not where the record says. The record names it relative to its own directory; `--spec` overrides that when it has moved. |
| `spec-not-a-bare-filename` | The record's `spec_path` reaches out of the record's own directory, or is absolute. A record is committed beside the document it names, so its basename is what finds it and what the record's own name is derived from; anything else decides the round against a document the record does not sit next to, and resolves only on the machine that wrote it. Judged on the record whether or not `--spec` names a document, since `spec_path` is what the record claims regardless of where the document is read from. |
| `untrimmed-revision` | A revision keeps the newline `git hash-object` prints. That newline compares unequal to the same content written without it, so an acceptance that changed nothing would pass as an incorporation. In practice this is the only surrounding whitespace that reaches here: every other form fails the schema's pattern first and is reported as `schema`. Judged over the revisions the adjudication reads — the one attacked, and the first acceptance of each proposal the round holds. One left on a rejection, on a disposition naming a proposal the round does not hold, or on a second verdict for a proposal already judged decides nothing, and refusing the record over it would hide the error that names the disposition itself. |
| `no-lenses` | The bundled lens registry is one the emitter would refuse to emit from — see its row above. Coverage is read off that registry, so a round in hand cannot have come from a registry like this, and reading coverage off it credits the record with attackers that never ran. |
| `mixed-revision-notation` | The record writes revisions in both notations, so one content would read as two revisions and an acceptance that changed nothing could pass as an incorporation. Judged over the same revisions as `untrimmed-revision`: a notation used only where nothing reads it refuses nothing. |
| `lens-missing` | A declared lens has no report. A lens that errored or returned unreadable output leaves the round unfinished, and an empty proposal list never stands in for a report. Coverage is containment, not equality: the declared set must be reported, and a record reporting more than that is surplus coverage rather than a defect — so retiring a lens leaves the rounds it ran in closed, where adding one reopens them. A misspelled lens name still refuses the round, since the lens it was meant to name goes missing. |
| `duplicate-lens` | A lens reports more than once. Coverage is read off one entry per lens. Names are matched the way the filesystem matched them when the prompts landed, so two spellings differing only in case or in Unicode form are one lens reporting twice rather than two lenses — they were one prompt file and so one attacker. Fires on any repeated name, including one the registry no longer declares. |
| `unreported-proposal-lens` | A proposal is attributed to a lens that files no report in this round. A lens that produced a proposal reported, so this one traces to no attacker the record names. Held against the record's own reported set rather than the registry's declared one: a record naming a retired lens carries an entry for it, so its proposals still trace and the round stays closed. |
| `contradicted-empty-report` | A lens reports empty, yet proposals are attributed to it. |
| `contradicted-proposals-report` | A lens reports proposals, yet none are attributed to it — a proposal it made and the record lost is a hole nobody adjudicates. |
| `duplicate-proposal-id` | Two proposals carry one id, so a disposition naming it adjudicates neither. |
| `unadjudicated-proposal` | A proposal has no disposition. The round closes only once every proposal is accepted or rejected. |
| `duplicate-disposition` | One proposal is adjudicated more than once. |
| `unknown-proposal-id` | A disposition names a proposal the round does not hold. |
| `unincorporated-acceptance` | An acceptance names the revision it attacked. Accepting a proposal without changing the document leaves it unadjudicated. |
| `stale-revision` | The document is not carrying every revision the record accounts for: in a round that accepted something, one an acceptance names; in a round that accepted nothing, the revision attacked. Either the document moved on after the round, and the new revision must be attacked or the proposals re-adjudicated against it — or an accepted proposal's incorporation never landed, and the edit is missing. A record whose acceptances name several different revisions always lands here: the document can only be in one state, so acceptances name the revision it reached once every accepted proposal was in it. Before editing the document, check the revision was written the way the check reads one: take the object id with `git hash-object --no-filters`, since the plain form runs the repository's clean filters and a document with CRLF endings then hashes as though its endings were LF. |
| `ordering-violation` | `--implementation-started` was declared — written bare, since a denial in either spelling (`--implementation-started=false` or `--implementation-started false`, over `false`, `0`, `no`, or `off`) declares nothing — and this run did not close the round — including when it could not read far enough to judge one, since a record that cannot be read has certainly not closed anything. The attack runs before that work, never alongside it. A denial declares nothing and does not make the command line valid either: the flag takes no value, so the `=` spelling is refused as `bad-arguments`, and one written after a space is taken for the record's name when no record was given. |
